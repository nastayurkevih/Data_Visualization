# ML-трек: Taipy

## Запуск

1. Используйте Python 3.11–3.13, затем из корня проекта выполните
   `python data/prepare_data.py`.
2. Установите зависимости из корневого `requirements.txt`.
3. Сохраните обученный sklearn-совместимый estimator или Pipeline в
   `ml_taipy/models/incident_classifier.joblib`.
4. Запустите `python ml_taipy/app.py` и откройте адрес, напечатанный Taipy.

В `app.py` показаны таблица карточек и интерактивная диаграмма Taipy GUI на
основе Plotly. Агрегация по вердикту выбрана как наиболее понятный первичный
срез для триажа. `callbacks.py` выносит инференс и SHAP в
`invoke_long_callback`, чтобы тяжелые вычисления не блокировали GUI.

`model.py` задает контракт из семи плоских признаков: тип, критичность,
источник, группа поддержки, название детекции и число объединенных инцидентов.
Сохраняемая модель должна принимать DataFrame с этими именами и возвращать
0/1, где 1 — FP. Эта модель намеренно не включена: ее нужно обучить отдельно
на явно размеченных строках. Объекты с вердиктом «Не указан» имеют
`is_false_positive = NA` и не должны использоваться как отрицательный класс.

SHAP-кнопка строит график и таблицу средней абсолютной важности признаков на
первых 200 строках. Это placeholder-визуализация глобальной важности; для
локального объяснения отдельного алерта нужно добавить выбор строки и
показывать направление вкладов, а перед защитой проверить объяснения на
обученной модели.

## Ограничения прототипа

- Без файла `.joblib` запуск приложения работает, но запуск инференса/SHAP
  завершится явной ошибкой в журнале Taipy и сообщением в интерфейсе.
- Данные этого датасета размечены крайне несбалансированно и содержат много
  неопределенных исходов; оценивать качество на «не указан» как на отрицательном
  классе нельзя.
- До обучения исключайте из признаков `verdict`, `Решение`, флаги FP/ложного
  срабатывания и любые поля, заполненные по результатам разбора.
